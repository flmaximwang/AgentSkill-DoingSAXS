# 把下机的 batch 数据归类成"每样品一个文件夹"

这条任务只做一件事：**把平铺在一个目录里的几十个 series 拆成"一个样品一个文件夹"，并让每个文件夹恰好含"该样品 + 前后两个背景"**。它是还原流水线的第 0 步——不先归类，后面"选出某个样品的 20 帧"就没有可靠依据。

## When to Use（什么时候用）

- 线站 batch 模式刚下机：一个目录里平铺着十几个到几十个 series。
- 用户问「这批数据怎么按样品分开」「哪个是背景/缓冲液」「pb7 / ddh2o 放哪」「归到 SEC-SAXS 还是 Tube-SAXS」。
- 已有目录结构看起来被手工对调过（旧实验的文件夹整批换了位置），需要在动手前先看清现状。
- **不负责**：积分 / 平均 / 扣减（→ `reduce-saxs-frames-to-curves`）；连续洗脱的 SEC 系列（→ `process-sec-saxs-series`）。

## 数据形状（batch 下机的文件约定）

- 一个 series = `<名字>_<4 位 run 号>_<5 位帧号>.<ext>`；同 series 帧号从 `00001` 连号（惯例约 20 帧）。
- 每个 series 的文件清单：N 个 `.tif` + N 个 `.txt`（每帧一份，**头里有 `Description:` = 样品名、`Run Number` = run 号、`Timestamp`、`Transmitted_Beam`**）+ 1 个 `<series>_00001.log`（帧时间戳 + 上传服务器路径）+ 1 个 `<series>.Intensity`。
- **样品身份只从帧 1 的 `Description:` 字段取，不要从文件名前缀猜**：样品名可能自带缓冲液后缀（`877-apo-pb7` 是"在 pb7 里测的 877-apo 样品"，不是背景 pb7）。
- run 号 = 测量顺序。背景与样品是**夹心**排列：`背景, 样品, 背景, 样品, …`。
- 衍生产物（RAW 导出的 `S_A_<series>_00001.dat` / `.out`、`S_A_<series>_00001_01.log`）**不以 series 名开头**——只做前缀匹配会把它们孤儿化。用"文件名包含 `<series>_`"兜底匹配。

## 归类规则（这就是任务的判据）

1. **背景 series** = `Description` **精确等于**用户点名的背景名（典型 `pb7`、`ddh2o`；换批可能换名）。
2. 每个背景 series 归给**按 run 号距离最近的样品**；距离平局（夹在两个样品之间）→ **两个样品文件夹都放**。
3. 样品文件夹名 = `Description` 原文（用户会说"名字为样品名"）。
4. 结果形状：中间每个样品 = 自己 + 前一背景 + 后一背景；首尾样品只有一侧。
5. 落盘用**复制**，源目录保持原样：共享背景必须同时出现在两个文件夹里，移动做不到；源目录是"能重做"的保险。
6. 目标目录的既有名字要先做**大小写折叠比较**（见坑 1）。

## 给下游还原流水线的交接（归类不是终点）

归类产物就是下游的输入契约，两个约定必须在归类时就定死，否则下游只能靠启发式重新猜：

1. **下游按「文件名前缀 == 文件夹名」精确相等区分样品/背景**（不做子串匹配）。所以文件夹名必须与样品 series 的前缀一致，且前缀精确匹配时代外理处理所有不属于样品的 run——包括线站已经归好类、后来又剩在 batch 里的那些。遗留样本：`877-apo-pb7` 这种"在 pb7 里测的 877-apo"，子串判背景会把整个样品判成背景。
2. **落盘时另写一份机器可读的配对清单**（样品名 → 内含 run + 哪个前缀是背景，例如 `_grouping.json`）：下游脚本直接读，不必各自重实现一遍前缀启发式，也不会因为"文件夹里多出一个 run"而静默扣错背景。

**必须随数据一起交给下游的两个物理事实**（归类阶段顺手记进清单，或至少提醒下游）：

- **样品 run 与 control run 之间有 1–3% 的通量/管位差**：透射归一化消不掉它，扣减后会留一个近常数的高 q 残差（`q²I` 在高 q 翘起来）。下游要用相对缩放（RAW 的 relative scale）补一把，**取样窗口选"粒子不散射"的高 q 区**——窗取低了会把样品自己的信号当背景扣掉。实测一条 6 样品稀释序列 + 5 个单独样品：因子落在 1.000–1.024。
- **`.cfg` 里两个开关默认是关的**：`ImageHdrFormat=None` + `EnableNormalization=False` → 逐帧 `.txt` 头**根本不会被解析**，透射归一化**静默失效**（集成的 I 会差 1/Transmitted_Beam 倍，本机实测 2.25 倍）。这两个值在归类阶段看不出来，但决定了整批数据能不能还原，必须写进交接清单。

## 执行步骤

1. **看清现状再动手**：把源目录与目标目录一次列清（`find <base> -maxdepth 2 -type d`），确认目标目录里已有的文件夹、以及它们是不是刚被手工搬过。**不要按记忆里的路径写**——用户改口"归到别的目录"、或两边目录被对调，都是真实会发生的。
2. **抽 series 列表与身份**：按 `<name>_<run>_<frame>.tif` 归并出 series → 读各自 `<series>_00001.txt` 的 `Description` / `Run Number`。
3. **先打计划表给用户看，再落盘**：一行一个样品（样品名 / run 号 / 文件数 / 内含哪些 series，并标注哪个是背景）。归类是"哪个文件进哪个文件夹"的判断题，先给结论比事后解释便宜。
4. **复制 + 逐字节校验**（`shutil.copy2` → sha256 比对源文件），再核对目标目录的文件集合与计划集合完全一致（多一个少一个都算失败）。
5. **报告三个数**：每个文件夹的文件数、"进了两个文件夹"的背景个数、以及**只进了一个文件夹的背景**——后者必须点名并给出理由（run 号距离算出来的），否则看起来像漏放（判据见 references）。
6. 源目录是否清理，问用户。不要默认删。

可直接调用：`scripts/group-batch-into-sample-folders.py`（默认 dry-run，`--apply` 才落盘；内建大小写折叠闸与 sha256 校验）。

## 坑（每条都会静默出错）

1. **大小写不敏感卷上的静默合并**（macOS APFS / Windows）：目标目录已有 `bsa` 时，`os.makedirs(".../BSA", exist_ok=True)` **不报错**，`os.path.isdir` 把大小写不同的名字判成同一目录，随后所有 `copy` 落进那个**已有实验**的文件夹——两批数据混在一起。规则：创建前把目标目录的既有条目取出来 `casefold()` 比较，命中就停下来要用户裁决（改名 / 确认合并）；不要指望 `mkdir` 报错。（跨平台通则见 `filename-portability`。）
2. **样品名自带背景后缀**：`877-apo-pb7` 含 "pb7"，用子串判背景会把整个样品判成背景。必须 `Description` **精确相等**。
3. **前缀匹配漏衍生产物**：`S_A_<series>_*.out/.log` 不以 series 名开头 → 用包含匹配兜底，否则它们要么被留下、要么被塞进别的样品。
4. **两类背景的交界处必然有两个"落单"背景**：紧邻另一个背景、而不是紧邻样品的那个，按"最近样品"只进一个文件夹。这是规则的必然结果，不是漏放——报告里要算给用户看，别等他来问。
5. **只在数量上校验会漏错**：文件数对得上，内容也可能来自另一个 series。逐文件 sha256 比对源目录，并核对**文件集合**（不是个数）。
6. 用户先给了错误的目标目录、后改口，是正常修正：改口后要把已落盘的产物**搬过去**，并清理留在旧目录里的东西——同时检查旧目录是否原本就有别的实验数据（别顺手搬错）。
